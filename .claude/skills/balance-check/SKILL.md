# 밸런스 점검

이 게임의 약속은 "하루 한 번, **10분**, 모두 같은 조건". 수치를 고치면 이 약속이 깨지기 쉽다(실제로 2분 43초, 20분 무한 생존이 모두 나온 적이 있다). 이 스킬은 그걸 매번 같은 방법으로 잰다.

## 순서

1. 저장소 루트에서 두 번 돌린다. 둘 다 끝까지 기다린다(몇 분 걸린다).
   ```bash
   node tests/balance-sim.mjs 5
   node tests/balance-sim.mjs 3 0.05
   ```
   - 첫째: 60fps로 5일 패턴(11-03 ~ 11-07)
   - 둘째: 20fps(느린 컴퓨터)로 3일. 프레임 속도에 따라 결과가 크게 다르면 그것도 문제다
2. 각 줄에서 **생존 시간**과 **서버 검증** 결과를 읽는다.
3. 아래 기준으로 판정한다.

| 판정 | 조건 |
|---|---|
| 통과 | 모든 줄이 생존 **7분 ~ 12분**이고 서버 검증이 모두 "통과" |
| 너무 어려움 | 생존 7분 미만인 줄이 있음 |
| 너무 쉬움 | 생존 12분 초과인 줄이 있음 (20분 00초 = 끝나지 않음, 가장 나쁨) |
| 검증 깨짐 | "거부"가 하나라도 있음 (명령이 exit 1로 끝난다). **가장 먼저 고칠 것** |
| 프레임 의존 | 같은 날짜의 60fps와 20fps 생존 시간이 2분 넘게 차이 남 |

봇은 가까운 몹을 피해 움직이며 가장 가까운 몹을 조준하는 "보통 플레이어" 흉내다. 실제 사람은 더 잘하거나 못할 수 있으니 범위를 넓게 잡았다.

## 보고 형식

```

| 날짜 | 60fps 생존 | 20fps 생존 | 점수 | 서버 검증 |
|---|---|---|---|---|
판정: 통과 / 너무 어려움 / 너무 쉬움 / 검증 깨짐 / 프레임 의존
```

## 판정이 통과가 아닐 때

수치를 **직접 바꾸지 말고** 어느 손잡이를 어느 방향으로 돌릴지 제안만 한다. 사용자가 고르면 바꾸고 이 스킬을 다시 돌린다.

| 손잡이 (파일) | 쉽게 하려면 | 효과 |
|---|---|---|
| `KILL_THREAT` (rules.js) | 내리기 | 처치할 때 위협도가 덜 오른다. 잘하는 사람이 덜 빨리 어려워진다 |
| `hpScale`, `dmgScale`의 나누는 수 (rules.js) | 키우기 | 위협도당 몹 체력·공격력 증가가 완만해진다 |
| `OVERTIME` (rules.js) | 키우기 | 급격히 강해지는 구간이 늦게 온다. **끝나지 않는 문제**가 생기면 내리기 |
| `spawnInterval` (rules.js) | 최소값·기울기 완만하게 | 몹이 덜 몰려온다. 기울기는 반드시 -1보다 완만하게 (서버 상한 계산의 전제) |
| `PLAYER`, `UPGRADES` (game.js) | 올리기 | 플레이어가 강해진다. 강화는 **더하기**로. 곱하기로 끝없이 늘리면 끝나지 않는다 |

"검증 깨짐"이면 수치가 아니라 `rules.js`의 `spawnBound`(출현 상한)가 게임의 출현 계산과 어긋난 것이다. `game.js`의 `spawn()`과 같은 순서로 위협도를 계산하는지부터 본다.
